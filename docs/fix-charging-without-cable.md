# Исправление: «идёт зарядка» на стоянке без кабеля

Источник — коммит `3fde1da` «Зарядка без кабеля не считается, прогноз с первого километра»
(12.10.2026). Здесь только часть про зарядку, в виде, пригодном для переноса в другой проект.

## Симптом

Машина стоит, кабель не подключён, а приложение показывает, что идёт зарядка: чип
«Зарядка DC · 34,5 кВт», баннер зарядки, флаг зарядки в виджете. Повторялось на каждой остановке.

## Причина

Машина **не обнуляет мощность DC после окончания сессии**. Функция мощности DC продолжает отдавать
последнее значение прошлой зарядки, пока не начнётся следующая. Снято с ГУ на стоянке: кабеля нет,
функция DC отдаёт 34,5 кВт.

Признак зарядки строился только на мощности:

```kotlin
// ChargeState
val energyFlowing: Boolean
    get() = powerKw != null && powerKw >= CHARGING_MIN_POWER_KW   // 0,3 кВт

// RangeEngine.detectCharging
if (tick.charge?.energyFlowing == true && (parked || standing)) return true
```

Залипшие 34,5 кВт проходят порог 0,3 кВт, машина стоит — условие истинно. Состояние кабеля при
этом читалось, но в решении не участвовало.

## Исправление

Одна проверка в месте, где сырые показания сводятся в состояние зарядки
(`ChargingDecoder.decode`): если машина явно говорит, что кабеля нет, мощность считается нулевой.

Было:

```kotlin
fun decode(plugged: Boolean?, acKw: Float?, dcKw: Float?, minutesLeft: Int?): ChargeState {
    val isDc = (dcKw ?: 0f) > (acKw ?: 0f)
    val power = if (isDc) dcKw else acKw ?: dcKw
    val state = ChargeState(plugged = plugged, powerKw = power, isDc = isDc)
    return if (state.energyFlowing) state.copy(minutesLeft = minutesLeft) else state
}
```

Стало:

```kotlin
fun decode(plugged: Boolean?, acKw: Float?, dcKw: Float?, minutesLeft: Int?): ChargeState {
    // Без кабеля энергия идти не может. Мощность DC машина после сессии не обнуляет:
    // функция продолжает отдавать последнее значение, пока не начнётся следующая зарядка.
    if (plugged == false) return ChargeState(plugged = false, powerKw = 0f)
    val isDc = (dcKw ?: 0f) > (acKw ?: 0f)
    val power = if (isDc) dcKw else acKw ?: dcKw
    val state = ChargeState(plugged = plugged, powerKw = power, isDc = isDc)
    return if (state.energyFlowing) state.copy(minutesLeft = minutesLeft) else state
}
```

Ранний выход заодно сбрасывает `isDc` и `minutesLeft` — они тоже остаток прошлой сессии.

### Важные детали

- **`plugged` — три состояния.** `true` — кабель есть, `false` — машина ответила, что кабеля нет,
  `null` — ни один источник не ответил. Обнуляем только при явном `false`. При `null` поведение
  прежнее: если гасить мощность и на `null`, настоящая зарядка пропадёт всякий раз, когда не
  прочиталось состояние кабеля.
- **Править нужно в одном месте — до всех потребителей.** После этого и признак зарядки в расчёте,
  и чип на экране, и флаг в виджете, и частота опроса зарядки берут уже исправленную мощность.
  Отдельные проверки «а есть ли кабель» в каждом потребителе не нужны.
- **Запасной признак по росту SOC оставлен.** Если состояние кабеля ошибочно придёт как «нет» во
  время настоящей зарядки, её всё равно поймает рост SOC стоя (больше 0,15 п.п. между опросами).

## Откуда берётся состояние кабеля

Два пути, функция в приоритете, свойство — запасной вариант:

```kotlin
const val PLUG_STATE_CONNECTED = 0x24130213
const val PLUG_STATE_DISCONNECTED = 0x24130212
const val OBC_CC_CONNECTED = 1

fun plugged(plugFunction: Int?, obcCc: Int?): Boolean? = when (plugFunction) {
    PLUG_STATE_CONNECTED -> true
    PLUG_STATE_DISCONNECTED -> false
    else -> obcCc?.let { it == OBC_CC_CONNECTED }
}
```

| Что | Идентификатор | Значения |
|-----|---------------|----------|
| Состояние кабеля, функция (`FUNC_CHARGING_PLUG_STATE`) | `0x24130200` | `0x24130213` — вставлен, `0x24130212` — нет |
| Состояние кабеля, свойство (`OBC_STS_CC`) | `0x2140A800` | `1` — вставлен |
| Мощность AC, функция / свойство | `0x24205400` / `0x2140A6B3` | кВт / ×0,1 кВт |
| Мощность DC, функция / свойство | `0x24207100` / `0x2140A6B4` | кВт / ×0,1 кВт — **залипает после сессии** |

Свойство `OBC_STS_CC` читается, только если функция не вернула ни одно из двух известных значений.

## Сопутствующее изменение в том же коммите

Из-за ложных пометок страдал и расчёт запаса хода. Каждая точка буфера несла флаг
`chargingLikely`, а окно 5 / 15 / 30 км отказывалось считать, если в срезе есть хоть одна такая
точка:

```kotlin
// RangeWindows.estimate — удалено
if (slice.any { it.chargingLikely }) {
    return RangeWindow(windowKm, WindowStatus.CHARGING, chart = chart)
}
```

Ложная пометка ставилась на каждой остановке, поэтому после каждой остановки окно приходилось
проезжать заново целиком. Проверку убрали: расход в окне и так считается по счётчику «потрачено
на вождении» (`consumedSocPoints`), в который скачок SOC от зарядки не попадает. Проверка на разрыв
данных (`gap`) осталась.

Переносить это нужно, только если в другом проекте есть такая же блокировка окна по флагу зарядки
**и** расход считается способом, нечувствительным к зарядке внутри окна. Если расход там считается
прямой разницей SOC на границах окна, убирать блокировку нельзя — зарядка внутри окна исказит
результат.

## Тест

```kotlin
@Test
fun stalePowerWithoutCableIsNotCharging() {
    // Снято с ГУ на стоянке: кабеля нет, а функция DC всё ещё отдаёт 34,5 кВт прошлой сессии.
    val stale = ChargingDecoder.decode(plugged = false, acKw = 0f, dcKw = 34.5f, minutesLeft = null)
    assertFalse(stale.energyFlowing)
    assertFalse(stale.isDc)
    assertEquals(0f, stale.powerKw!!, 0f)
}
```

## Что перенести в другой проект

1. Найти место, где мощность зарядки превращается в признак «заряжается».
2. Убедиться, что состояние кабеля читается и различает «нет кабеля» и «не ответило».
3. При явном «нет кабеля» считать мощность нулевой — до того, как её увидят расчёт и экран.
4. Сбросить вместе с мощностью тип зарядки (AC/DC) и оставшееся время.
5. Оставить запасной признак по росту SOC, если он есть.
6. Добавить тест на залипшую мощность без кабеля.
7. Если буфер или журнал хранит пометки зарядки по точкам — учесть, что уже записанные ложные
   пометки останутся в сохранённых данных до их вытеснения.

## Что не проверено

- Исправление сделано по показаниям, снятым на стоянке, и покрыто модульным тестом. Подтверждения
  с машины уже после исправления в коммите нет.
- Чтение мощности и времени на настоящей зарядке в этом проекте ещё не подтверждено
  (см. `docs/features/range/overview.md`).
- Залипание наблюдалось у мощности DC. Залипает ли так же мощность AC — не проверялось; проверка
  по кабелю закрывает оба случая.
